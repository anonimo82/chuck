# TextIO (experimental)

Procedural Unicode text, with no markup or CSS. TextStyle owns font family, absolute pixel size (1–512), bold/italic/underline flags (0/1), packed RGB (0–0xffffff). Defaults Sans 16px, black, regular. Property setters return accepted value or -1 (empty string for invalid font); invalid input preserves state. inherit(style) copies properties. TextDocument owns ordered paragraphs with style snapshots; addParagraph(text,style), paragraphCount(), paragraphText(index), setParagraphText(index,text), setParagraphStyle(index,style), removeParagraph(index), clear(). UTF-8 validated, 64 KiB per paragraph, 1 MiB total, 4096 paragraphs. Empty paragraphs allowed. Invalid index text query returns empty string. measureParagraph(index,width,int[] dimensions) uses Pango/Cairo plain-text layout, word/character wrapping, width 1–4096 pixels, exact two-element output [logical width,height] in pixels; invalid input preserves output. Font fallback and measurements depend on installed fonts. Style changes affect stored paragraphs only via setParagraphStyle. No new package dependencies: pangocairo and GLib already used. This first stage does not render/export documents or implement mixed inline styles, tables or real-time processing. Native validation pending.

## Advanced typography

TextStyle adds weight (100–1000, default 400; bold getter is true at >=700, bold setter selects 400 or 700), strikethrough (0/1), backgroundColor (-1 disabled or packed RGB), letterSpacing (-32..128 pixels), baselineShift (-512..512 pixels, positive upwards), script (0 normal, 1 superscript, 2 subscript), opacity (0..1). Script scales glyphs to 70% and adds a baseline shift of +0.35 or -0.2 times original font size; explicit baselineShift is additive. These are procedural Pango attributes, no markup parsing. Invalid integer setters return -1 except backgroundColor (-2); invalid float setters return NaN; state remains unchanged. Inheritance and paragraph snapshots include all attributes. Colors, background, opacity and decorations are prepared in the layout for later rendering; this release exposes measurements, not visible output. Measurements depend on installed fonts. Native validation pending.

## Inline runs

TextRun owns UTF-8 text and a style snapshot. set(text,style), setText(text), setStyle(style), text(). TextDocument.appendRun(paragraph,run) appends a nonempty run after the original base text; runCount, runText, setRun, setRunStyle, removeRun address appended runs only (zero-based). paragraphText returns the concatenated base and run texts. setParagraphText replaces the complete content and discards runs; setParagraphStyle changes only the base style. Run snapshots are independent of later object edits. Maximum 1024 appended runs per paragraph and 16384 per document, existing byte limits still apply. Pango receives byte-range attributes for each UTF-8 segment; no markup. KeyframeCurve values can be assigned to TextStyle and applied using setRunStyle. Rendering pending; native smoke validation pending.

## Paragraph layout

TextParagraphStyle separates block layout from glyph style. alignment: 0 left, 1 center, 2 right, 3 justify (last line not justified; automatic RTL can mirror left/right). wrapMode: 0 word with character fallback, 1 character, 2 word only. direction: 0 automatic, 1 LTR, 2 RTL. lineSpacing is extra pixels between lines (0..512), indent first-line offset (-1024..1024; negative hanging indent), marginLeft/Right/Top/Bottom (0..2048 px). Defaults zero. Invalid int setters return -1; invalid float setters return NaN; unchanged state. inherit copies properties. setParagraphLayout(index,style) stores a snapshot, getParagraphLayout(index,style) copies it out. Content and inline styles remain independent. measureParagraph includes margins; measureDocument(width,int[2]) returns max paragraph logical width and sum of heights (no collapsing margins, no pagination). Width 1..4096, positive inner width and absolute indent smaller than inner width required. Word-only wrapping may overflow horizontally. Measurements are logical, not ink bounds; rendering pending. Both measurement APIs share makeLayout for future rendering. Keyframes can control all numeric properties. Native validation pending.

## Raster rendering

TextDocument.exportPixels(width,height,backgroundRGB,int[] pixels) renders the document to straight RGBA8, row-major, exact width*height*4 elements. savePNG(path,width,height,backgroundRGB) saves a new lowercase .png file (never overwrites). Background -1 is transparent, otherwise packed RGB opaque. Dimensions 1..4096, at most 4194304 pixels. Shared Pango layout includes mixed runs and paragraph properties. Paragraphs stack vertically with measured rounded heights; horizontal content is clipped to margins and canvas, vertical overflow clipped to canvas; no pagination or scrolling yet. All layouts validated even if offscreen. Empty documents render background only. Invalid requests leave arrays unchanged and do not create output files. Compatible with RasterImage.importPixels and, with opaque background, VideoWriter.appendFrame. Glyph appearance depends on installed fonts. Rendering is synchronous/offline, not audio-thread safe. No new dependencies. Native validation pending.

## Paragraph containers

TextContainer is a reusable box configuration attached to one paragraph via setParagraphContainer(index,box); getParagraphContainer copies its snapshot out. paddingLeft/Right/Top/Bottom 0..512 px, borderWidth 0..128 px, borderColor packed RGB, backgroundColor -1 transparent or packed RGB, opacity 0..1 for the whole decorated paragraph. Defaults are zero padding/border, transparent background, opacity 1. inherit copies all properties. Invalid setters preserve state (NaN for floats, -1 for borderColor, -2 for backgroundColor). Margins remain external; padding and border reduce the available line width and increase logical measured dimensions. The painted box fills the available width between margins; measurements report logical content width plus padding/borders/margins rather than the painted width. Decorated content is clipped inside the box. Opacity composites the entire box as a group, including text. Zero opacity preserves layout. Existing default paragraph rendering is unchanged. Container snapshots survive text edits; no nested or multi-paragraph containers yet. KeyframeCurve can control numeric properties. Native validation pending.

## List items

TextList configures an individual paragraph list marker. mode 0 none (default), 1 bullet, 2 decimal number with period, 3 custom marker. number 1..999999 (default 1), level 0..16, levelIndent 0..128 px (default 20), markerWidth 1..512 px (default 32). marker accepts nonempty UTF-8 up to 64 bytes, no tabs or line breaks, default '*'. setParagraphList(index,list) copies a snapshot; getParagraphList copies it out; paragraphListLabel returns the computed marker separately from paragraphText. Numbers are explicit, allowing procedural numbering; no automatic renumbering or nested list tree yet. Marker uses base text style, a left-hand gutter of level*levelIndent+markerWidth, with wrapping confined to body; marker clipped to its gutter. Height includes both marker and body. Container opacity applies to both. Text and run editing preserve list metadata. Numeric properties can be driven by keyframes. Invalid setter preserves state, returns -1 for ints, NaN for floats, empty string for marker. Native validation pending.

## Tables

TextTable.create(rows,columns) resets a rectangular table, 1..256 rows, 1..32 columns, at most 1024 cells. rows(), columns(), setCell(row,column,text,TextStyle), cellText, setCellLayout(row,column,TextParagraphStyle), setCellContainer(row,column,TextContainer), columnWeight(column[,value]) (0.01..100, default 1). Cell indices zero-based. Cells default to 1 px black border, 4 px padding and transparent background. Each row takes the maximum measured cell height, cells fill that row, columns share available width by relative weight with rounded cumulative boundaries. Borders are independent, not collapsed. Text wraps within each cell. TextDocument.appendTable(table) takes a snapshot at the current paragraph insertion boundary, setTable(index,table) replaces it in place, tableCount(), removeTable(index). Tables and paragraphs render in insertion order; removing a paragraph adjusts table boundaries, clear removes all. paragraphCount and paragraphText exclude tables. Document table limits 256 tables, 4096 cells, 1 MiB cell text in addition to paragraph budget. No spanning, nested tables or mixed runs in cells yet. Document measurement includes full table width and row heights. Invalid layouts leave output arrays unchanged. Native validation pending.

## Editorial grids

TextGrid.create(rows,columns) creates a rectangular panel layout with transparent, borderless, unpadded panels by default. Limits and columnWeight semantics match TextTable. setPanel(row,column,text,TextStyle), panelText, setPanelLayout, setPanelContainer customize panels. columnGap and rowGap are integer pixels 0..512, default 0, invalid returns -1. Gaps are excluded before allocating relative column widths and included between measured row heights; no outer gap. Gaps reveal canvas background. Numeric controls accept keyframe values (integer conversion for gaps). TextDocument.appendGrid, gridCount, setGrid, removeGrid use independent zero-based grid indices, preserving interleaved paragraph/table/grid insertion order and snapshots. Table and grid blocks share the existing aggregate limits. No panel spans, multi-paragraph panels, nested panels or free positioning yet. Native validation pending.

## Pagination

TextPage is reusable page configuration: width/height 1..4096 px (default 640x480), marginLeft/Right/Top/Bottom 0..2048 integer pixels, backgroundColor packed RGB or -1 transparent (default white). Canvas limit 4194304 pixels and positive content area required. TextDocument.pageCount(page) returns number of pages (empty document one blank page), -1 on invalid layout. exportPage(page,index,int[] pixels) produces straight RGBA8, exact page.width()*page.height()*4 elements; savePagePNG(path,page,index) creates new lowercase PNG, never overwrites. Indices zero-based. Greedy pagination preserves paragraph/table/grid insertion order, moving whole blocks to the next page when necessary; any block taller than the available content height rejects the entire plan, rather than silently clipping. No paragraph or table row splitting, headers/footers or explicit breaks yet. Maximum 4096 pages. Each query recomputes the plan; numeric settings can be changed by keyframes. Rendering shares the existing document drawing engine, clips to the page content area, and leaves ordinary exportPixels/savePNG behavior unchanged. Native validation pending.

## Recursive node foundation

TextNode is a value-owned tree with kind() 0 group (default), 1 paragraph. setParagraph(text,TextStyle) replaces the complete node with a paragraph leaf (UTF-8, up to 65536 bytes); text() returns its content. clear() resets to empty group. Groups support appendChild(node), insertChild(index,node), setChild(index,node), getChild(index,destination), removeChild(index), childCount(). copyFrom(node) copies a complete tree. All input/output nodes are independent snapshots, so object reference cycles cannot arise; direct self insertion/replacement and getChild into the source root are rejected. Indices zero-based; mutations return 1 success, 0 failure. depth() counts root as 1, nodeCount() includes root, textBytes() counts UTF-8 paragraph content bytes. Limits per tree: 32 depth, 4096 nodes, 1 MiB text. Mutations validate before insertion, preserving state on invalid requests. This PR introduces structural storage only: no document attachment, recursive measurement or rendering yet. Existing document APIs remain unchanged. Future stages add decorated groups, composite cells and recursive rendering. Native validation pending.

## Recursive decorated containers

TextNode.setContainer(TextContainer) copies decoration; on a plain group it changes kind from 0 to 2 (decorated container) without removing children. Paragraphs remain kind 1. Both groups and decorated containers accept arbitrary child nodes under existing limits. getContainer copies decoration out. setLayout/getLayout copy TextParagraphStyle; group layout stores external margins for future recursive rendering (paragraph-only controls have no group semantics). gap([float]) is spacing between group children, 0..512 px, default 0; paragraphs reject it. setStyle/getStyle apply only to paragraph leaves. setText replaces leaf text while preserving style/layout/box, unlike setParagraph which resets the node. All properties are value snapshots and may be driven by KeyframeIO. This stage stores decoration and layout metadata; recursive rendering and document attachment are still pending. Existing TextDocument rendering unchanged. Native validation pending.

## Recursive tables

TextNode.createTable(rows,columns) resets a node to kind 3, with 1..256 rows, 1..32 columns and at most 1024 cells. Each cell is a child node in row-major order, initially an empty decorated group (1 px border, 4 px padding). rows(), columns(), columnWeight(column[,value]) (0.01..100) describe geometry. setCellNode(row,column,node) replaces the entire cell snapshot, including its decoration; getCellNode copies it out. To preserve the default cell decoration, retrieve it, append content, then set it back. Cells accept any supported node, including another table or a multi-paragraph decorated group. Generic childCount/getChild can inspect cells, but append/insert/setChild/removeChild and gap are rejected on tables to preserve rectangular invariants. Node/depth/text budgets include cells and nested tables; invalid edits preserve state. Existing TextTable APIs remain unchanged. This stage stores recursive tables; rendering and document attachment follow in the recursive renderer stage. Native validation pending.

## Recursive grids and lists

TextNode.createGrid(rows,columns) creates kind 4, sharing the rectangular cell API and relative weights of recursive tables, with undecorated group cells and integer columnGap/rowGap (0..512). TextNode.createList(TextList) creates kind 5 with a nonzero marker mode. Direct children are list items and can be any node, including another list. appendChild/insertChild/setChild/removeChild and gap work on lists. itemLabel(index) returns the marker; ordered lists number children consecutively from TextList.number, so edits renumber automatically. Nested lists have independent numbering. setList/getList copy marker settings for paragraph and list nodes; mode zero is valid only for paragraphs. Geometry, node budgets and snapshot rules remain unchanged. Recursive measurement, document attachment and drawing follow in the next stage. Native validation pending.

## Recursive document rendering

TextDocument.appendNode(TextNode), nodeCount(), getNode(index,destination), setNode(index,node), removeNode(index) attach independent top-level tree snapshots. Nodes share insertion order with legacy paragraphs, tables and grids; paragraph removal adjusts anchors; clear removes all. Up to 256 roots, aggregate 4096 recursive nodes and 1 MiB tree text in addition to legacy budgets. measureDocument, exportPixels, savePNG, pageCount, exportPage and savePagePNG include recursive trees. A recursive geometry plan measures each child once per pass; groups stack children with gap, rectangular nodes use weighted columns and equal-height cell boxes per row, lists reserve a marker gutter and number direct children automatically. Group margins, padding, borders, backgrounds and opacity apply to the whole subtree; nested clipping and compositing are supported. Paragraphs use existing Pango layout; list group markers use default typography. Width is the available block width for recursive nodes, even if text is narrower. Pagination treats each root as an indivisible block; oversized roots reject the plan. Numeric properties can be sampled from KeyframeIO, then snapshots replaced explicitly. No recursive page splitting, cell spanning or live bindings yet. Native validation pending.

## Native document persistence (version 1)

TextDocument.saveNative(path) saves a new lowercase .cktxt file, returns 1 on success, 0 on failure, never overwrites. The format uses magic CKTXTDOC, little-endian uint32 version 1, fixed-width little-endian integer fields, IEEE-754 binary64 and length-prefixed UTF-8. Paragraphs include base byte count, text runs, typography, layout, decoration and list settings. Tables, grids and recursive nodes preserve their complete properties and canonical relative insertion order. No pointers, native struct dumps, derived counters or external font files are serialized. Maximum encoded size 32 MiB. Separate TextPage and KeyframeCurve objects are not part of TextDocument and are not stored. Loading is deferred to the next stage. See native-format.md for the field order.

### Native loading

TextDocument.loadNative(path) reads version 1 .cktxt into a temporary document and commits only after all validation succeeds. Invalid extension, magic/version, UTF-8, out-of-range or nonfinite fields, inconsistent run text, geometry, depth, aggregate budgets, block ordering, truncation or trailing bytes are rejected. Existing content is preserved on failure. Round-trip serialization is canonical; external page/keyframe objects remain outside this format. No checksum means structurally valid content changes cannot always be detected. Native validation pending.

## Plain text (TXT)

TextDocument.loadTXT(path) replaces the entire document with default-styled paragraphs, one per line. Accepts lowercase .txt, UTF-8 with optional initial BOM, LF, CRLF and CR; preserves empty lines including a final empty line after a terminal newline. Empty files produce an empty document. Invalid UTF-8, embedded NUL, I/O errors and existing paragraph limits (65536 bytes per paragraph, 4096 paragraphs, 1 MiB aggregate text) reject the import without changing the original document. File input is bounded to 8 MiB.

TextDocument.saveTXT(path) writes UTF-8 without an added BOM, normalizes line endings to LF and never overwrites an existing file. Paragraphs include all inline text and list labels; legacy and recursive tables/grids use tabs between cells and newlines between rows; groups and list items use newlines, with list markers included. Top-level insertion order is preserved. No escaping is applied to embedded tabs or newlines: this is a lossy human-readable export, not a structured interchange format. Empty documents produce empty files; a single empty paragraph has the same representation. Styling, geometry and pagination are not exported. Output is bounded to 8 MiB. Both methods return 1 on success, 0 on failure. Use .cktxt for lossless document persistence. Native smoke validation pending.

## SVG vector export

TextDocument.saveSVG(path,width,height,backgroundRGB) creates a new lowercase .svg file using the shared Pango/Cairo document renderer directly on an SVG 1.1 surface. Returns 1 on success or 0 on failure, never overwrites, and removes incomplete output on rendering or writing errors. Canvas limits and clipping match savePNG (1..4096 per dimension, at most 4194304 total pixels; background -1 transparent or packed RGB). All legacy and recursive blocks, inline styling, list labels, borders and decorations follow the existing renderer. Cairo normally exports glyph outlines rather than editable text; font appearance depends on installed fonts at export time. Cairo may use raster fallback for unsupported compositing operations. Output is a single canvas, not paginated. The SVG viewBox uses the requested dimensions; Cairo 1.16+ uses px units, older versions may emit pt units. No new package dependencies; requires Cairo built with SVG surface support. Native smoke validation pending.

## Multipage PDF export

TextDocument.savePDF(path,page) writes a new lowercase .pdf file using the same greedy page plan as pageCount, exportPage and savePagePNG. Returns 1 on success, 0 on failure; never overwrites, rejects invalid layouts before opening the output and removes incomplete files on rendering or writing errors. All pages use the supplied TextPage dimensions, margins and background; -1 leaves the page background unpainted (PDF viewers generally display white). Logical pixels convert to PDF points at 96 px per inch (0.75 pt per px). The existing page limits, indivisible blocks and 4096-page limit apply; an empty document produces one blank page. Rendering targets Cairo PDF directly rather than embedding whole-page raster images; Cairo may use raster fallback for unsupported operations. Fonts and text extraction depend on Cairo/Pango and the installed fonts. No new package dependencies; requires Cairo built with PDF surface support. Native smoke validation pending.

## Explicit page breaks

TextPage.addBreak(blockIndex) and removeBreak(blockIndex) insert or remove a forced page boundary before a zero-based top-level block in document insertion order (paragraph, table, grid or recursive node). Index 0 is rejected; accepted indices are 1..4607, and a layout rejects indices outside the actual document. Duplicate insertion and removal of absent indices return 0; successful changes return 1. breakCount(), breakAt(index) (sorted indices, -1 for invalid index), and clearBreaks() inspect or reset the configuration. Explicit breaks and automatic overflow share the same page planner; an explicit boundary coinciding with overflow creates only one page. Blocks remain indivisible. Break indices refer to positions, not stable identities; update them after structural edits. These are TextPage settings, not part of the native document format; raster canvas and TXT/SVG export are unaffected. All paginated APIs share the break settings. Native validation pending.

## Repeating page headers and footers

TextPage.setHeader(text,style,height) and setFooter(text,style,height) store independent snapshots of UTF-8 text and TextStyle and reserve a band of 1..2048 logical pixels within the existing page margins. The header appears above the body and footer below it on every page, including an empty document. Text uses the existing paragraph renderer and wraps to the available width. If a band cannot fit its content or leaves no positive body height, pagination fails. Setters return 1 on success or 0 for invalid text, style or height; headerHeight() and footerHeight() return the reserved height (0 when disabled). clearHeader() and clearFooter() disable the respective band. pageCount, exportPage, savePagePNG and savePDF share the reserved geometry. Page settings remain external to native document persistence; nonpaginated exports are unchanged. Native validation pending.

## Automatic page numbering

TextPage.numbering([value]) enables (1) or disables (0, default) placeholder expansion in repeating header and footer text. TextPage.firstNumber([value]) controls the first displayed page number (1..999999, default 1); invalid setters return -1 and preserve state. When enabled, {page} expands to firstNumber plus the zero-based page index, and {pages} expands to the actual document page count independently of firstNumber. Double braces escape literal braces ({{page}} renders as {page}); unknown placeholders remain literal. Existing static text remains unchanged when numbering is disabled. Page planning first computes the body pagination, then validates each expanded band against the reserved height and existing UTF-8 byte limit. Invalid expanded geometry rejects pagination and exports. All paginated outputs use the same substitutions. Page settings remain external to native persistence; no nonpaginated export changes. Native validation pending.

## Paragraph continuation across pages

TextPage.splitParagraphs([value]) enables (1) or disables (0, default) splitting top-level paragraphs across page boundaries. Invalid setters return -1 and preserve the previous setting. In enabled mode a paragraph may fill the remaining page and continue on successive pages at measured Pango logical line boundaries; the original layout, mixed runs, indentation, list marker and decoration remain in one shaped layout, rendered in vertically clipped slices. Top and bottom spacing belong to the original layout, rather than being repeated on each slice. Explicit page breaks still refer to original top-level block indices, not fragments. An indivisible line (including its relevant spacing or decoration) that cannot fit an empty page causes pagination to fail. Glyph ink extending beyond logical line boundaries may be clipped at a page boundary. Tables, grids and recursive nodes remain indivisible. The option applies to pageCount, exportPage, savePagePNG and savePDF; the native document and nonpaginated exports are unchanged. This is same-width page continuation, not yet reflow into heterogeneous linked text frames. Native validation pending.

## Table continuation across pages

TextPage.splitTables([value]) enables (1) or disables (0, default) splitting top-level TextTable blocks between complete rows. Invalid setters return -1 without changing the setting. Rows retain their original cell content, styles, column weights and geometry. Row gaps are retained within each fragment but not across page boundaries. A row taller than the available body of an empty page rejects pagination. TextGrid and recursively nested TextNode blocks remain indivisible. Repeated table headings and splitting individual cells are not supported. Explicit page breaks still refer to original block indices. The setting applies to pageCount, exportPage, savePagePNG and savePDF, independently of splitParagraphs. Native persistence and nonpaginated rendering are unchanged. Native validation pending.

## TextFrame geometry foundation

TextFrame stores independent integer x/y positions (0..4095), width/height (1..4096), and zero-based page index (0..4095). Defaults are (0,0,320,240), page 0. Each property has a getter and validated setter returning -1 on invalid input. setGeometry(x,y,width,height) validates atomically and returns 1 on success or 0 on failure. setContainer(TextContainer) and getContainer(TextContainer) copy decoration and padding settings by value. contentSize(int[2]) returns the floored inner width and height after padding and border, or 0 without modifying the array if geometry has no usable interior or array size is incorrect. reset() restores defaults. Geometry is independent of any particular page; page bounds will be checked during composition. Numeric setters can accept values sampled from KeyframeIO after integer conversion. This is the geometry foundation only: text assignment, linking, reflow, rendering and persistence are not yet implemented. Native validation pending.

## Ordered TextFlow chains

TextFlow owns a sequence of up to 256 independent TextFrame snapshots in insertion order, avoiding circular references by construction. appendFrame(frame), setFrame(index,frame), getFrame(index,destination), removeFrame(index), frameCount() and clearFrames() manage the sequence. setText(text,style) copies a UTF-8 string (up to 65536 bytes) and a single TextStyle. layout() measures available interior dimensions and distributes the source in Pango line-boundary slices, rewrapping the remainder for each successive frame. A frame too short to fit a line receives an empty fragment and the remainder continues to the next frame; a frame with invalid interior geometry rejects the layout. frameText(index) returns the assigned source substring, or an empty string for invalid index or stale plan. ready() indicates a successful current layout, not that all text fits. Source or frame mutations invalidate the plan; call layout() again. Changes to external frame objects require setFrame() to update the snapshot. At this stage only a single style is supported; overflow reporting, mixed runs, rendering and persistence follow in later PRs. Native validation pending.

## Mixed styles and overflow in TextFlow

TextFlow.appendRun(TextRun) appends an independent styled snapshot to the current source, up to 1024 nonempty runs and 65536 total UTF-8 bytes. setText replaces the source and clears runs. Layout preserves run attributes when slicing and rewrapping the remaining text at each frame's own interior width and height, including when a boundary falls within a run. overflowBytes() returns unassigned UTF-8 bytes (0 when fully assigned, -1 before a successful current layout); overflowText() returns the exact unassigned suffix (empty for a stale plan or no overflow). A successful layout with no frames reports the full source as overflow. Frame and source mutations invalidate these queries. Rendering and persistence are not yet provided. Native validation pending.

## Linked frame page composition

After layout(), TextFlow.pageCount() returns the highest frame page index plus one (0 for an empty chain, -1 for a stale plan). exportPage(page,width,height,backgroundRGB,pixels) fills an exact-size straight RGBA integer array; savePagePNG(path,page,width,height,backgroundRGB) writes a new lowercase PNG, never overwrites. Canvas limits match TextDocument. All frame rectangles must fit the supplied common canvas; sparse page indices produce blank intermediate pages. Frames are painted in insertion order, including empty decorated frames. Padding, border, background and opacity apply to the entire frame. Mixed text uses the same remaining-source Pango layout as planning and is clipped at the assigned logical line boundary; overflow is not drawn. No implicit layout, document-page integration or native persistence. Native validation pending.

## Native TextFlow persistence (version 1)

TextFlow.saveNative(path) and loadNative(path) use independent lowercase .ckflow files, with magic CKTXFLOW and little-endian uint32 version 1. The serialized fields are: source UTF-8 string, base byte count, base style, run count and each run string/style, frame count and each ordered frame (x, y, width, height, page; padding left/right/top/bottom, border width, border RGB, background RGB, opacity). Strings, styles, colors and binary64 values use the same encoding as .cktxt (see native-format.md). No pointers, derived layout, fragments or pixel data are saved. Maximum file size 2 MiB. Save never overwrites; load validates limits, UTF-8, run consistency, finite numeric values, geometry fields, version and exact end of file before replacing the original. Successful load invalidates layout; call layout() explicitly. Frame geometry may be stored even when the interior is unusable, as with the existing setters; layout detects that condition. .cktxt version 1 is unchanged. Native validation pending.

## Logical reading order and text ranges

TextDocument.plainText() returns a logical reading-order string with list labels, tab-separated cells and newline-separated blocks, using the same traversal as saveTXT (without its line-ending normalization). TextFlow.sourceText() returns the complete source including mixed runs and overflow, independent of layout. After successful layout, frameStartByte(index) and frameEndByte(index) expose half-open UTF-8 byte ranges in source order, including empty frames; invalid indices or stale layout return -1. These are programmatic accessibility building blocks, not OS accessibility integration or tagged PDF. No native format changes.

## TextFlow plain text interchange

TextFlow.loadTXT(path, TextStyle) imports lowercase .txt files as a single styled source, retaining the frame chain, replacing mixed runs and invalidating layout on success. UTF-8 with optional initial BOM is accepted; CRLF and CR normalize to LF, preserving empty lines and final newlines. Invalid UTF-8, embedded NUL, missing files and normalized sources over 65536 bytes are rejected without modifying source or layout. Raw input is bounded to 131075 bytes. TextFlow.saveTXT(path) writes the complete source including overflow, without BOM, with LF normalization; it needs no current layout and never overwrites. TXT does not preserve styles or frame geometry; use .ckflow for lossless persistence. Native validation pending.

## TextDocument and TextFlow interoperability

TextDocument.appendFlow(TextFlow) appends the complete source (including overflow) as one paragraph, with independent copies of the base style and inline runs. TextDocument.exportParagraphToFlow(index, TextFlow) replaces the destination source with an independent copy of the selected paragraph's inline content, preserves its frame chain, and invalidates layout. Paragraph layout, decorations and list markers are not transferred: those are distinct from frame geometry. Both operations return 1 on success or 0 on invalid arguments or document limits, without changing the destination on failure. No implicit layout or native format changes. Native validation pending.

## TextFlow layout storage optimization

The derived frame plan stores half-open source byte ranges and logical clipping heights rather than duplicated fragment strings. frameStartByte and frameEndByte now perform constant-time lookup; frameText constructs the requested substring on demand. Remainder layout construction avoids copying discarded runs. Frame geometry, rendering, invalidation, public API and native formats are unchanged. The new regression group covers empty slices, UTF-8 boundaries, repeated layouts, source and frame mutation and the 256-frame limit. Native validation and performance measurements pending.

## TextFlow end-to-end workflow

See [text-flow-example.ck](text-flow-example.ck) for a standalone example of styled document content, heterogeneous linked frames, byte ranges, PNG output and native/TXT persistence. Run from a writable directory with TextIO available to ChucK; remove or rename existing output files before rerunning. The example produces two PNG pages, example.ckflow and example.txt. Mutations invalidate layout; call layout() before reading ranges or rendering. Native load preserves styles and frame geometry but requires fresh layout; TXT import preserves destination frames but replaces styles. Reading-order APIs are logical, not platform accessibility integration. Regression coverage now includes a document-to-flow-to-native-to-document workflow, matching rendered pixels after native reload and complete TXT export despite overflow. Native validation pending.

## Frame-local hit testing

TextFlow.hitTest(index, x, y) maps a point in frame-local pixel coordinates (origin at the frame's outer top-left, including padding and border) to a zero-based UTF-8 insertion byte offset in the complete source. Uses Pango cluster trailing positions, clipped to the assigned frame range. Within the visible line band, points past the glyphs map to the nearest insertion position. Returns -1 for stale layout, invalid index, nonfinite coordinates, empty frames or points outside the visible text interior. Does not create a cursor, selection, GUI widget or change the source. Native validation pending.

## TextFlow logical selection

setSelection(anchor,focus) accepts zero-based UTF-8 byte boundaries, including the source end and reversed selections; invalid endpoints return 0 and preserve state. selectionAnchor()/selectionFocus() preserve direction; selectionStart()/selectionEnd() return the sorted half-open interval; selectedText() returns its source substring, including overflow. clearSelection() collapses to focus. Selections do not require or invalidate layout. Frame changes and appendRun preserve endpoints; replacing the source via setText, loadTXT, loadNative or exportParagraphToFlow resets selection to zero on success. Selection is transient and not stored in native files. Boundaries are Unicode code-point boundaries, not necessarily grapheme boundaries. No selection highlighting or GUI integration. Native validation pending.

## TextFlow source editing

insertText(position,value), deleteText(start,end), replaceText(start,end,value), and replaceSelection(value) return 1 on success, 0 on failure. Offsets are UTF-8 byte boundaries; explicit ranges are ordered and half-open. Existing styled fragments survive edits; inserted text uses the source base style. Successful edits collapse selection to the end of the insertion and invalidate layout, except empty no-op edits which only collapse selection. Invalid ranges, UTF-8, source sizes above 65536 bytes or more than 1024 runs leave source, frames, selection and layout intact. No grapheme-aware editing or undo history. Explicit styled insertion is a subsequent milestone. Native validation pending.

## Styled TextFlow editing

Overloads insertText(position,value,style), replaceText(start,end,value,style), and replaceSelection(value,style) copy the explicit TextStyle into inserted content. applyStyle(start,end,style) replaces the complete style on a half-open UTF-8 interval without modifying text or selection; empty ranges are successful no-ops. styleAt(position,result) copies the style of the character beginning at a valid byte boundary into a supplied TextStyle; source-end and invalid offsets fail without changing result. The source base style remains the default for plain insertion. Existing run and byte limits apply; failures preserve state. Styles are value snapshots and use existing native persistence. No partial-property formatting or run coalescing is introduced. Native validation pending.
